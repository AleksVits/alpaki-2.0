# Перевірка інтерфейсу — 04.10.2026

Результат: основний і touch-аудити та функціональні регресійні перевірки пройшли в Chromium. У WebKit (рушій Safari) пройшли аудит виходу за межі та перевірка основних сценаріїв. Firefox не перевірявся. `npm run build` і `npm run lint` проходять без помилок і попереджень.

## Покриття в Chromium

Середовище: локальний Vite, Chromium через Playwright. Перевірки розмірів виконуються в браузерній емуляції, а не на фізичних пристроях.

- 17 viewport: 320×568, 375×667, 390×844, 430×932, 720×1024, 768×1024, 844×390, 900×700, 901×700, 1024×768, 1366×768, 1279×800, 1280×800, 1440×900, 1580×900, 1920×1080, 2560×1440, 3840×2160.
- Усі 13 основних секцій, обидві мови. Перевіряються вихід видимих елементів за межі секції/екрана, помилки JavaScript і локальні HTTP-помилки. Горизонтальні стрічки з власним скролом виключені з перевірки виходу за межі.
- Окремий touch-прохід: 320×568, 390×844, 768×1024, 1024×768.
- Знімки чотирьох станів апартаментів та модального вікна на шести розмірах.
- Регресійні перевірки: фокус і Escape у меню, історія браузера та hash-переходи, вибір поверху, відкриття/закриття галереї, порожні стани будівництва, модальне вікно на низьких екранах, відстань між pager і стрілкою, зміна категорії інфраструктури, збереження полів форми, контекст запиту в повідомленні, порядок екранів у пейджері апартаментів, єдиний `h1`, окрема адреса англійської версії та відновлення збереженої мови.
- Окремо перевіряються звичайна анімація вступу, меню на touch-екрані 320×480 та reduced motion.

## Покриття у WebKit

Середовище: WebKitGTK 2.52 (MiniBrowser через WebKitWebDriver) на Linux. Це той самий рушій, що в Safari, але не сам Safari: шрифти, скляні ефекти та жести на iPhone потрібно додатково переглянути на реальному пристрої.

- Аудит виходу за межі: 447×844 (вужче вікно цей браузер не дозволяє), 768×1024, 1366×768, 1920×1080; усі 13 секцій, обидві мови — без зауважень.
- Сценарії: поява шапки, меню з блокуванням сторінки, перемикання мови з адресою `/en/` і відновлення збереженої мови, перехід за пунктом меню, модальне вікно політики, вибір апартаментів, галерея архітектури, категорія інфраструктури, локальний шрифт без звернень до Google Fonts, розмиття скляних панелей.
- Геометрія елементів порівняна з Chromium на п'яти розмірах: розбіжності обмежуються кількома пікселями через різну метрику тексту; окремі заголовки на вузьких екранах переносяться в іншому місці.

## Запуск

Потрібен доступний модуль `playwright`. Якщо модуль наданий зовнішнім runtime, задайте `PLAYWRIGHT_PATH` як абсолютний шлях до цього модуля. Не додавайте машинозалежні шляхи до коду.

Змінні середовища (`qa/browser.cjs`):

- `QA_ENGINE` — `chromium` (типово), `webkit` або `firefox`. Для WebKit і Firefox рушії потрібно один раз встановити: `npx playwright install webkit firefox`.
- `QA_CHANNEL` — канал Chromium, типово `msedge` (потрібен встановлений Edge). Порожнє значення запускає Chromium із Playwright.
- `QA_URL` — адреса сайту, типово `http://127.0.0.1:5173/`.
- `QA_OUTPUT` — каталог результатів, `QA_TOUCH=1` — touch-прохід аудиту.

З каталогу `web` запустіть `npm run dev -- --host 127.0.0.1`. В іншому терміналі з цього ж каталогу:

```powershell
$env:QA_OUTPUT = "$env:TEMP/alpaki-qa"
node qa/audit.cjs
node qa/states.cjs
node qa/regression.cjs
$env:QA_TOUCH = '1'
node qa/audit.cjs
Remove-Item Env:QA_TOUCH
npm run build
npm run lint
```

Ті самі сценарії в рушії Safari або у Firefox:

```powershell
$env:QA_ENGINE = 'webkit'   # або 'firefox'
node qa/audit.cjs
node qa/regression.cjs
Remove-Item Env:QA_ENGINE
```

Зібраний сайт містить готову розмітку, яку скрипт «оживляє», тому ті самі сценарії варто проганяти й на ньому. Після `npm run build` запустіть `npm run preview -- --host 127.0.0.1` і вкажіть адресу:

```powershell
$env:QA_URL = 'http://127.0.0.1:4173/alpaki-2.0/'
node qa/regression.cjs
node qa/audit.cjs
Remove-Item Env:QA_URL
```

`audit.cjs` і `regression.cjs` повертають ненульовий код за виявлених помилок. `states.cjs` зберігає геометрію та знімки для ручного огляду. Для окремого збереження desktop/touch результатів використовуйте різні `QA_OUTPUT`. Мова запам'ятовується між відвідуваннями, тому аудит явно вибирає її перед кожним проходом.

## Збірка для публікації

Мінімізатор CSS у Vite (Lightning CSS) змінює деякі пари властивостей, тому в стилях діють два правила:

- префіксну властивість пишемо перед стандартною: `-webkit-backdrop-filter`, потім `backdrop-filter`. За зворотного порядку у збірці залишається лише префіксна, яку Chrome і Firefox не розуміють;
- `rotate`, `scale` і `translate` не поєднуємо з `transform` в одному правилі: мінімізатор або відкидає окрему властивість, або зливає її з `transform`. Потрібні перетворення записуємо в один `transform`.

Після зміни стилів варто переглянути саме зібраний сайт: `npm run build`, потім `npm run preview`.

## Межі готовності

Форма готує `mailto`-лист: сервера заявок у проєкті немає, доставка не підтверджується. Телефон лишається явно позначеним демонстраційним номером, Telegram веде на загальну адресу сервісу. Дані планувань і текст політики містять наявні заглушки; реальні дані не вигадувалися.

Локальна збірка оновлює `../docs` для ручної публікації; автоматичну публікацію виконує GitHub Actions (див. README у корені). QA-сценарії нічого не публікують і не пушать.
